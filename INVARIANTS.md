# Invariants

Hard constraints. A change that breaks one of these is wrong even if tests pass. IDs are stable; reference them as `I<n>`.

## Baseline data

- **I1** **`internal/baseline/data/*.json` is generated by `cmd/sctimport` and never edited by hand.** Changes go through `cmd/sctimport/sources.json` and regeneration.
  Enforced by: review only. `baseline.Load` rejects unknown fields and `Validate` rejects inconsistent settings, but a hand-edited value with valid shape passes.

- **I2** **Every baseline is traceable to a pinned Microsoft download.** The source URL is under `https://download.microsoft.com/` and the zip's SHA-256 is recorded.
  Enforced by: the SHA-256 check in `generate` (cmd/sctimport/main.go); `TestEveryBaselineIsTraceable`.

- **I3** **Each GPO component in a package is either included or explicitly excluded with a reason.** The generator fails on anything it can't represent. It never drops data silently.
  Enforced by: the "neither included nor explicitly excluded" check and the error paths in `generate` (cmd/sctimport/main.go).

- **I4** **At most one baseline applies to any (product type, build) pair.**
  Enforced by: `Catalog.checkOverlap`, run by `baseline.Load`; `TestCatalogSelect`.

- **I5** **A setting has exactly one payload, its ID is the canonical ID for that payload, and IDs are unique within a baseline.**
  Enforced by: `Setting.Validate` and `Baseline.Validate` (internal/baseline/baseline.go); `TestValidateRejectsInconsistentSettings`.

- **I6** **Both `//go:embed` directives stay in place** (they are directives, not comments; see I19): `data/*.json` in internal/baseline/catalog.go and `scripts/*.ps1` in guest/guest.go. Without them the build still compiles, but the plugin ships with no baselines and no guest scripts.
  Enforced by: `TestCatalogSelect` and `TestEveryBaselineIsTraceable` for the baseline data. Review only for the guest scripts.

## Packer session safety

- **I7** **No setting is applied that the protection rules haven't cleared.** Every non-compliant setting goes through `plan.Protect` inside `plan.Build`, and only `ActionApply` and `ActionGuard` items are applied.
  Enforced by: `plan.Build`; `TestProtect*` and `TestBuildAndVerify`.

- **I8** **Protection rules fail closed.** When the guest state needed to decide is unknown (e.g. `f.WinRM == nil`), the setting is deferred, not applied.
  Enforced by: `registryRule` and `firewallRule` (internal/plan/protect.go); `TestProtectWinRMService`, `TestProtectFirewall`.

- **I9** **Guarded changes are registry-only and snapshotted, and the rollback task is armed before they are applied.**
  Enforced by: `applyGuarded` (provisioner/guard.go) checks for restorable state and calls `ArmGuard` before `apply`; `Invoke-SWRollback` rejects non-registry kinds.

- **I10** **A setting is `hardened` only if the apply step succeeded and re-inspection matches the baseline.** Anything else is `failed`.
  Enforced by: `plan.Verify`; `TestBuildAndVerify`.

- **I11** **`mode = "strict"` makes no change when any setting would be deferred.**
  Enforced by: the strict-mode check in `run.execute` (provisioner/provisioner.go), which runs before any apply; `TestExecuteReadOnlyModes`.

- **I12** **The plugin runs only over WinRM, in an elevated, 64-bit PowerShell session.**
  Enforced by: the `ConnType` check in `Provisioner.Provision` and the elevation and 64-bit checks in `run.detect`.

## Scope

- **I13** **Only supported, in-lifecycle releases with an implemented baseline are hardened.** Domain controllers, end-of-support releases, unknown builds and client LTSC editions on a build without a known LTSC release are rejected.
  Enforced by: `facts.Classify` and `Catalog.Select`, called from `run.selectBaseline`; `TestClassify`, `TestCatalogSelect`.

- **I14** **Only computer configuration below HKLM is configured.** User Configuration GPOs are excluded components.
  Enforced by: `generator.addRules` reads `ComputerConfig` only; guest registry access goes through `Get-SWRegistryRoot` (64-bit HKLM).

## Architecture

- **I15** **The guest scripts make no decisions.** Baseline selection, applicability, WinRM protection and compliance are decided in Go. Guest actions only detect, read and write state.
  Enforced by: review only.

- **I16** **`provisioner/config.hcl2spec.go` matches `Config`.** Regenerate it with `make generate` whenever a `mapstructure` field changes.
  Enforced by: review only (there is no `go:generate` directive).

- **I17** **An incompatible change to the report JSON increments `report.SchemaVersion`.**
  Enforced by: review only.

- **I18** **`make check` passes before a change is committed.**
  Enforced by: `make check`, locally and directly in `.github/workflows/build.yml`.

- **I19** **Source code has no comments except documentation: Go doc comments and PowerShell comment-based help.** In Go, every function and method, unexported and test functions included, has a doc comment that starts with its name, describes non-obvious parameters under `Parameters:`, has a `Returns:` list when it returns an error or more than one value, and ends with `Author: Lars Krogh` and `Version: x.y.z` lines. Every exported type and every non-test package has a doc comment. No other Go comments are allowed. Generated files (`// Code generated ... DO NOT EDIT.`) are exempt. In PowerShell, the only comment allowed is a comment-based help block (`<# .SYNOPSIS ... #>`), and every `.ps1` file and every function has one. Script help goes directly after `#Requires`, followed by two blank lines so it isn't attached to the first function. Function help goes at the top of the function body. Each block contains `.SYNOPSIS`, `.DESCRIPTION`, `.PARAMETER` for each parameter, at least one `.EXAMPLE`, `.OUTPUTS` when the function returns something, and `.NOTES` with `Author` and a semantic `Version`. Keep the existing author and raise the version when behavior changes. Functional directives are allowed in both languages: `//go:embed`, `//go:build`, `#Requires`. Everything else belongs in Markdown (`AGENTS.md`, `docs/`).
  Enforced by: `make doccheck`, part of `make lint`. `cmd/doccheck` rejects missing or misnamed Go doc comments, missing `Author`, `Version` and `Returns:` lines, and any other Go comment except `//go:` directives. `psdoccheck.sh` rejects any PowerShell comment outside a help block and any block without `.SYNOPSIS`. Whether the documentation is complete and accurate is checked in review only.
